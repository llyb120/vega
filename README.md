# Vega

Vue **3.6.0-rc.14 / Vapor** 前端 + **Nitro 2.13.5 / Node.js 24** 服务端。前后端一次构建、同源部署；业务状态保存于 **SQLite**（默认）或 **MySQL 8**，不依赖 Go、Rust、Tauri 或原项目目录运行。

## 运行

```powershell
npm ci
npm run build
$env:NITRO_HOST = '127.0.0.1'
$env:NITRO_PORT = '8080'
$env:VEGA_DB = 'D:/data/vega-nitro.db'
$env:VEGA_TOKEN = '<至少16个字符的随机访问令牌>'
npm start
```

访问 `http://127.0.0.1:8080`。首次打开时，使用`VEGA_TOKEN`（未配置则看启动日志中的初始化令牌）创建首个管理员，之后使用**用户名和密码**登录；初始化令牌不再能访问普通API。登录由HttpOnly、SameSite=Strict Cookie保存，每次成功登录后重新计算7天有效期（不是从首次登录固定计时），刷新页面和服务重启后仍有效；改密码/停用/改角色会撤销旧登录。部署请复制**整个 `.output`**（包括 `server` 与 `public`），在部署机安装匹配平台的原生 `sharp` 依赖。`npm run dev` 启动 Nitro；单独开发前端可运行 `npm run dev:web`，其 `/api` 代理到本机 8080。

Node >=24.10，使用内置 `node:sqlite`，无需另装数据库。默认数据库为工作目录的 `vega.db`，支持通过 `VEGA_DB` 指定位置。**不会自动转换或覆盖 Go 版/原 Nova 的数据库**；检测到不兼容数据库会拒绝启动，请指定新文件。

### 数据库配置

所有数据库读写都是异步的，不阻塞主线程：SQLite 在独立的 worker 线程中执行（WAL 模式），MySQL 使用连接池。

| 变量 | 说明 |
| --- | --- |
| `DB_TYPE` | `sqlite`（默认）或 `mysql` |
| `VEGA_DB` | SQLite 数据库文件（默认 `vega.db`）。**两种数据库下**，上传/归档文件都保存在它所在目录的 `files/` 下，需持久化并备份 |
| `MYSQL_URL` | 例如 `mysql://vega:密码@127.0.0.1:3306/vega`（密码中的特殊字符需 URL 编码）；设置后忽略下面的分项 |
| `MYSQL_HOST` / `MYSQL_PORT` / `MYSQL_USER` / `MYSQL_PASSWORD` / `MYSQL_DATABASE` | 分项配置，默认 `127.0.0.1` / `3306` / `root` / 空 / `vega` |
| `MYSQL_POOL_SIZE` | 连接池大小，默认 10 |

MySQL 需要 **8.0.19 及以上**（不支持 MariaDB），数据库须事先创建（建议 `CHARACTER SET utf8mb4`），首次启动自动建表。只支持单个 Vega 进程连接同一个库。示例：`docker compose -f docker/docker-compose.mysql.yml up -d --build`（见文件内说明）。

数据库结构版本为 6，**不做旧版本迁移**：版本不符的非空库会拒绝启动且不修改，请使用新库。

## 实时通信

登录后通过 `/api/events` 的 WS/WSS 承载小请求、对话和牛马实时事件。票据为一次性、15 秒有效并绑定登录与 CSRF；大附件、大请求及超过 256KiB 的 GET 响应继续使用 HTTP，登录/注销等 Cookie 操作也保留 HTTP。写操作使用单次请求 ID，断线只重新同步状态，不自动重放，结果不确定时须先核对。原业务权限与输入校验不变。

## 本机执行端

各台电脑启动新版 `vega-local` 后，只需在该电脑网页登录一次并确认站点授权。前端仅传递一次性登录票据，客户端直接向后端换取设备凭据、持久保存并通过 `/api/local-agent/socket` 建立独立连接；之后**关掉网页、浏览器后台休眠、客户端或服务端重启都不依赖网页**，联网后客户端自行重连。输入框旁按实际在线设备选择电脑，手机可选远端电脑且不会尝试本机连接。心跳容忍30秒，短暂断连保留原任务并给同一客户端实例60秒重连；执行中的操作不重发，客户端仅补传尚未确认的结果，连接恢复后自动续做；响应超时也先尝试一次重连接回结果，而非立即判定中断。超过恢复期限、客户端进程重启或结果仍不确定时才暂停、等待确认，不自动重放或换机。需同时升级服务端、网页和客户端，升级后在电脑端重新握手一次。详见 [local/README.md](local/README.md)。

## 账号、登录与权限

首次创建管理员后，进入「账号与权限」添加账号、停用/启用、调整角色或重置密码；没有开放注册，也没有内置默认密码。用户名3–64个英文字符/数字/点/下划线/连字符，密码至少12字符、最多256个UTF-8字节。密码采用随机salt的scrypt存储，Cookie中的随机会话令牌只以SHA-256摘要保存于SQLite，密码和登录Cookie不返回到账号列表。

| 角色 | 网站权限 |
|---|---|
| 管理员 `admin` | 系统配置、订阅/技能、数字牛马、Chrome和团队管理（密码本由各牛马创建者在牛马页配置）；创建/停用账号、修改权限，查看全部会话，并授予其他账号会话只读权限 |
| 操作用户 `operator` | 通过网站新建和运行自己的对话/Stage/Fire，查看自己的任务结果；不能直接调用管理员专属网站接口。已提交任务的内部工具集与运行机制不按网页角色裁剪 |
| 只读用户 `viewer` | 只能查看管理员明确授权的会话、其图片和实时事件；不能发消息、停止任务、创建会话或执行工具 |

会话、Stage/fork/Fire衍生会话按创建账号归属，实时WebSocket事件和截图BLOB也校验会话访问权限；分享只授予查看，不授予执行。衍生会话继承创建时的查看授权，之后单独管理。旧版本无归属的会话/截图只有管理员可见，不会因升级自动公开给新账号。SQLite新增账号/登录表，升级前仍建议备份数据库。

注销只撤销本次网页登录，不关闭已经独立授权的客户端。密码修改/管理员重置、角色变更或停用撤销该账号的网站登录、实时查看及设备凭据；服务端内部任务仍保持原执行机制，但设备授权撤销或断连超出恢复期限后，会暂停依赖该设备且结果不确定的操作，不自动重试；最后一个启用的管理员不能被停用或降级。内部agent、数字牛马、定时任务和恢复流程不依赖是否有人在线，保持原工具集/执行机制；只有网站上明确调用停止/取消等业务操作才改变执行状态。登录有失败尝试和并发KDF限流，用户名或密码错误统一返回失败；网站修改API要求CSRF token并检查Origin，不依赖前端隐藏按钮。

**能够通过网站提交内部任务的账号必须可信**：网站RBAC只保护登录、页面/API和数据查看，不是内部agent的工具授权系统，更不是操作系统级多租户沙箱。内部bash/文件/MCP和牛马工具保持原能力，可能访问同一容器或服务器。隔离不可信任务应单独运行容器/实例和数据卷，不能靠网页角色实现。只读用户没有提交任务或执行工具的网站入口。

### HTTPS与反向代理

网站和客户端均支持HTTP/WS与HTTPS/WSS；公网建议使用HTTPS。`VEGA_PUBLIC_URL`设置为实际访问的HTTP(S) origin（如`http://vega.example.com:8080`或`https://vega.example.com`，不带路径），服务按该origin检查请求，仅HTTPS使用Secure Cookie。**HTTP下登录信息、设备凭据与命令明文传输，存在被窃听或篡改的风险。** 不要信任任意客户端传入的Forwarded头。反代保留Host，为`/api/events`、`/api/chrome/live`、`/api/local-agent/socket`转发WebSocket Upgrade/Connection，设备连接还需保留Authorization头。直接本地HTTP开发可不设置此变量。

**实时通道与超时**：网页的所有API都走普通HTTP，`/api/events`只推送事件，不再转发API请求。服务端每20秒发送一次心跳并做协议级ping，网页75秒收不到任何消息才重连；重连带上次的事件序号，2分钟/5000条以内的断线只补发漏掉的事件，不整页刷新。牵牛星客户端每5秒心跳，大于256KB的结果改为`POST /api/local-agent/result`上传（同样需要保留Authorization头，并允许最大48MB请求体）。反代请据此设置：

- WebSocket读超时不低于75秒（nginx `proxy_read_timeout 120s; proxy_send_timeout 120s;`），且不要缓冲WebSocket；
- `client_max_body_size 90m`（聊天附件上限）以上，`/api/local-agent/result`的请求体可达48MB；
- 服务端已对超过2KB、且浏览器接受gzip的JSON接口响应做gzip（会话历史一般压缩到1/3以下，1200条的历史约2.0MB→0.6MB），反代无需再压缩`/api`；若反代也开启gzip，已带`Content-Encoding`的响应会被跳过；
- 每个账号最多同时保持12个实时事件连接（多开标签页/设备合计），超出的新连接收到4429并在30秒后重试；无响应的僵尸连接会在下一次心跳时被清理。

原`VEGA_TOKEN`现在仅用于**首个管理员初始化**和只返回就绪/扩展连接状态的`GET /api/health`，不再是普通网站API的管理员后门。容器启动/健康检查已改用health入口，不需要保存网站账号密码；Token轮换不撤销SQLite中的账号登录。

## Linux / Docker 自动安装扩展

项目根目录的 `Dockerfile` 会在Linux内构建Nitro和原生依赖，并在独立Go阶段编译Windows x64、Linux x64/ARM64、macOS Intel/Apple Silicon客户端；部署后从主导航「资源」直接下载当前镜像配套版本，无需另跑Go构建或访问外部Release。镜像同时运行同容器的专用无头Chromium。启动参数自动加载现有扩展，等待配对后报告就绪；无需手工打开扩展管理页，只发布8080，不暴露CDP/回环桥接端口。SQLite、浏览器登录态与工作目录通过卷持久化。

```sh
docker build --pull -t vega:local .
docker run -d --name vega --shm-size=1g \
  -p 127.0.0.1:8080:8080 \
  -e VEGA_TOKEN='替换成至少16字符的随机令牌' \
  -v vega-data:/data -v vega-workspace:/workspace vega:local
```

这是**自动加载容器里的扩展，不会改宿主浏览器**。默认保留Chromium沙箱，宿主限制namespace/sandbox时会停止并报错，不静默降低安全性；数据卷和basic password store的浏览器登录态须保护。完整操作、权限和沙箱说明见 [`docker/README.md`](docker/README.md)。

## 配置模型

设置页通过表单管理服务商、接口地址、密钥和模型，支持获取/搜索/手动添加模型与修改能力、长度参数；场景模型通过下拉选择，支持档位和备用顺序，浏览器场景只显示图片模型。高级请求头/厂商参数按需展开。底层仍支持旧`provider.options.baseURL/apiKey/headers`与顶层写法、嵌套分类、`limit.context/output`、`modalities.input`和`variants`。密钥可用`{env:NAME}`/`${NAME}`引用；`__stored_secret__`保留已有密钥。经验图谱独立导航，设置排在最后；界面不再提供目录配置或技术机制说明。

```json
{
  "model": "openai/gpt-4.1",
  "provider": {
    "openai": {
      "api": "openai-completions",
      "options": {"baseURL": "https://api.openai.com/v1", "apiKey": "{env:OPENAI_API_KEY}"},
      "models": {
        "gpt-4.1": {"limit": {"context": 128000, "output": 8192}, "modalities": {"input": ["text", "image"]}}
      }
    }
  },
  "scenes": {"lightweight": ["openai/gpt-4.1"], "coding": ["openai/gpt-4.1"], "computer": ["openai/gpt-4.1"]},
  "contextMode": "auto",
  "mcp": {},
  "image": {"baseURL": "", "apiKey": "", "models": []}
}
```

场景数组按顺序降级；电脑场景须支持图片。变体 ID 为 `provider/model/variant/high`。厂商目录支持原项目的 30 个 preset，账号目录优先于 models.dev 能力补全；Coding Plan 等没有 `/models` 的端点可回退 models.dev，但不能用目录补回账号无权限模型。

### 专有订阅

设置 →「服务商」选择CodeBuddy/WorkBuddy/Devin，点击登录会立即打开窗口、绑定本次来源/站点并自动检查结果，成功后直接导入账号模型。远程Devin默认回调网站的`/api/providers/callback/devin`，不再要求用户浏览器访问服务器的127.0.0.1端口；公网部署需设置正确的`VEGA_PUBLIC_URL`并使用HTTPS。回调独立校验一次性state/PKCE，轮询绑定发起管理员，错误/过期state不能交换Token。若官方限制回调地址，可改用手动回调登录并粘贴登录后完整跳转地址。CodeBuddy/WorkBuddy使用服务端轮询，不依赖客户端本机安装CLI；仅在点击「读取服务端已有登录」时使用部署端已有凭据。网站新登录优先于部署端旧CLI会话。真实账号及第三方回调白名单仍需在目标部署验收，协议夹具不能代替它。

- **CodeBuddy**：CLI 环境/登录优先，缺少时使用应用内登录；续期、账号/企业请求头、`/v3/config` 和本地 product 默认模型合并、CLI 可用模型过滤、reasoning summary、重复工具 ID/包装 JSON 归一化。
- **WorkBuddy**：独立认证与模型目录，不能误用 CodeBuddy 的账号；自动查找 `resources/app.asar.unpacked/cli`，使用 WorkBuddy 自己的 Electron helper 只读解密登录。设置页可指定安装目录/`WorkBuddy.exe`/内置 CLI 路径；`WORKBUDDY_EXE` 可显式指定解密运行时。
- **Devin**：读取 CLI TOML 或应用内登录；直接执行 Connect/Protobuf 推理，回传历史可见 reasoning（消息字段 5），校验 gzip 帧、trailer、停止原因与工具完整性；CLI 不可用时使用原项目的版本化模型快照。**Adaptive 自动路由与参考项目一样不支持，必须选具体模型。**
- **Codex / Claude Code**：按 CLI 配置识别自定义 API，否则在每次请求前只读订阅认证。官方端点固定，不执行 apiKeyHelper，不代替 CLI 轮换 refresh token；过期须先在 CLI 更新。macOS 支持原项目覆盖的钥匙串形态，其它 keyring 后端不会猜测。

### 数字牛马工作台

用户创建并选择牛马，直接交代目标；对话用于沟通和调度，执行会话由牛马内部创建/续写。管理员创建的是**团队牛马**，所有账号可见；普通成员创建的是**个人牛马**，仅本人和管理员可见。团队牛马的设置、删除、执行位置与浏览器登录环境由管理员管理，执行成员可以交代任务，只读账号只能查看。牛马添加即用，不再有启用开关或工作时间；职责的定时触发和任务暂停仍保留。旧单例数据原地作为团队“默认牛马”，任务和会话ID不变；网站不再提供历史会话或手动建会话入口，旧数据和兼容API仍保留。管理员另有只读“调试会话”页，可查看每个牛马真实的沟通/执行/浏览器会话及原始工具记录。

在牛马页切换客户端/服务端或选择设备，只更改**之后创建任务**的默认位置。每个任务在创建时快照设备和目录，原任务的续做、审批返回和子任务都保持原绑定；切换不会中断正在执行的任务，也不会把离线客户端任务改到服务端。浏览器仍使用牛马独立的服务端实例，两端文件不自动同步。

牛马页提供明确确认的删除入口；正在执行时须先停止任务和对话。删除会清除牛马职责、记忆、任务、沟通/执行会话和独立浏览器Profile，默认牛马删除后也不会重生；该牛马自己的密码本一并删除，不会删除项目文件。

只复用一套执行引擎和共享调度循环，不为每个牛马启动后端。全局最多3个任务并发，轮转调度牛马；同目录的写任务、同牛马的浏览器任务串行，不同牛马的浏览器可并行。等待补充、审批、外部作业时释放名额，到时续做原任务。牛马沟通会话不能直接执行命令或网页操作；任务必须以完整已验证计划和 `complete` 证据交付，普通结束一轮不算完成。

**通用自愈**复用原任务和执行会话：意外中断、超时、未知异常或未验证交付时，持久保存原因/尝试次数/恢复点，进入“检查现场→诊断→最小修复→验证→续做”的恢复模式。单轮最多15分钟，自动恢复最多3次，30/60/120秒退避，恢复窗口30分钟；耗尽后等待用户。服务重启不清零预算，停止/取消/驳回审批不自动恢复。外部操作结果不确定先核验，不能自动重放提交。进程本身的拉起仍由系统服务或容器负责。

**每牛马独立浏览器**：按需启动独立Chromium进程，登录态存于 `<数据库目录>/employee-browsers/<牛马ID>`，停止和重启不清除Profile。需要支持 `Extensions.loadUnpacked` 的现代Chrome/Chromium，可用 `VEGA_CHROME_PATH` 指定；Windows已验证Chrome156。牛马生成的扩展副本只连接自己的认证回环桥，启动调试使用私有管道，不暴露CDP端口；原始扩展保持不变。浏览器故障只影响所属牛马，恢复后重新观察，不重放页面操作。密码本按牛马独立配置（牛马页「密码本」，仅牛马创建者可查看列表和修改）：牛马的对话、任务和电脑会话只能取用自己的条目，须按条目的使用条件取用；凭据支援收到的临时条目存进请求方牛马且仅限原任务；删除牛马同时删除其密码本。普通会话不归属牛马，不提供密码本。旧版全局密码本在升级后首次启动时复制给当时所有牛马（临时条目只给所属任务的牛马）后删除。隔离Profile不等于操作系统沙箱，同业务账号仍共享服务端数据。

### 浏览器查看与远程操作

在牛马工作空间打开「浏览器」（执行成员仅限自己的牛马）；兼容全局浏览器仍仅管理员可访问。选择tab后通过同源WS/WSS持续更新视口画面，不再等待每次操作后的单张截图。默认只查看：电脑用滚轮以鼠标位置为中心缩放预览、按住鼠标拖动；手机用双指捏合缩放、单指拖动画面，手势只改变预览、不缩放整个应用窗口；「还原视图」恢复原始缩放和位置，键盘也支持 +/- 缩放、方向键平移、0 还原。只有点击「开始操作」后，点击、双击、右键、按住拖动、滚轮、文字输入与常用按键才会直接同步到网页；按钮随即变为「退出操作」，退出立即恢复查看模式。开始、退出操作均保留当前预览比例和位置，坐标按实际缩放换算；可通过「还原视图」恢复原始比例。鼠标拖动超过几像素即按拖动处理，不额外发送单击。拖动确认按下后，移动使用有界的最新位置流，不逐次等待往返；弱网下合并过时位置，松手优先发送并在最终位置释放。结束后显示「同步中…」直到释放结果对应的新画面显示，再接受下一次拖动，避免把第二次手势排到旧画面上。手机长按画面不打开图片菜单、不向网页发送右键或单击；操作模式短按点选网页，按住约半秒后移动会像鼠标按住拖动，松手、触摸取消或加入第二根手指会释放鼠标；未长按的滑动不会误发拖动。网页翻页请用「网页上滚/下滚」；也可前进/后退、重载及跳转HTTP(S)网址。操作模式下辅助输入框常驻：先点网页输入框，再点辅助框打开手机键盘，支持中文、输入法和粘贴；点「发送文字」只输入内容、不自动回车，提交须单独点「回车」。画面使用内存中的JPEG截图流，最高约10帧/秒，实际速度随页面、网络和扩展响应变化，**不是高帧率视频或桌面远程控制**。无需升级现有Chrome扩展。

WS连接先通过带CSRF校验的POST取得15秒有效、一次性且绑定当前账号和浏览器实例的票据；握手同时校验Cookie和Origin，注销/撤权会关闭已连接通道。慢客户端每次只保留一张待确认画面，不积压帧或点击；实时画面不写入SQLite。输入按连接序号去重，并校验用户实际显示过的帧、网页/视口和焦点，断线和结果不确定时不重放；原HTTP截图/操作接口仍保留，继续使用原像素校验规则。

手动控制期间独占**该标签页**的 Chrome 操作锁，同一标签页的 agent 后续操作等待；不同标签页的人工控制与 agent 任务互不阻塞，多 tab 可同时查看或操作。退出、断线、页面隐藏或30秒未操作会释放控制权，并在必要时松开鼠标。手动操作会使同页 agent 的旧观察失效，但纯查看不会覆盖 agent 的 ref/截图。获取后台/最小化标签画面可能会显示 Chrome 窗口并切到该页。

**无头模式**：设置 `VEGA_BROWSER_MODE=isolated` 后，服务启动一个私有无头 Chrome（与 Docker 同一套扩展协议、独立 profile 目录 `<数据库目录>/chromium`），不占宿主桌面。Linux/Windows/macOS 都支持；Windows 上通过 `VEGA_CHROME_PATH` 指定 chrome.exe，未设置时自动探测常见安装路径。无头实例可多 tab 并行截图和输入；cookie/登录态持久在私有 profile，不与用户日常浏览器共享。Docker 模式同样使用此变量，行为一致。

远程部署仍只需现有网站端口。反向代理须为`/api/events`、`/api/chrome/live`及`/api/local-agent/socket`转发WebSocket的HTTP/1.1 Upgrade/Connection并保留Host，设备连接还须保留Authorization；公网建议配置正确的`VEGA_PUBLIC_URL`并使用HTTPS/WSS，**不要暴露Chrome调试端口或回环扩展端口**。意外断线且没有进行中的操作时自动重连（最多3次），页面切回前台也会自动重连；可能已执行的操作仍要求人工核对，不自动补发上次操作。画面不变时只发送不含图片的确认帧，静止约2秒后采样降为每秒2帧。

## billion-context / ACP 与查漏记录

配置`"contextMode":"acp"`启用模型主动管理：模型收到稳定`[m00001]`引用与`<context-budget>`提示，用`compress`选择已完成单元并写摘要；可把`bN`作为边界精炼到T2/T3。`decompress`恢复原文及子块，`search_context`返回命中片段，`recall`按预算带回原文和工具配对，较长原文可用`read sqlite:message/序号`按行读取。账本、应急投影和token校准均保存在SQLite，不会覆写消息。

这是**历史虚拟化/分层压缩机制**，不是将模型原生窗口提升到十亿token。字符估算、图像占位成本和实测锚点之外的增长仍是估算；应急机械压缩会明确标注细节缺失，原文可回读。与所参考的Lyra一样，不实现上游kernel未被使用的young/old标签和默认关闭的按块数触发器。已有Vega数据库的旧块仍可恢复；新的压缩使用原子单元、至少40字摘要和70%收益校验，保护最近2个单元及未完成工具调用。

本轮还补上了：中断工具配对与孤儿修复、完成轮次OpenAI reasoning裁剪、每标签最近2份Chrome DOM投影、413旧图恢复、输出耗尽单次降思考且不重放工具、同会话MCP连接/describe状态保留、候选场景/同模型和只读路由、fork上下文账本、read的50KiB实际行边界与路径归一化。逐项来源和验收边界见`reference/parity-audit.md`。

`/setup`只允许更新provider/model/scenes；配置入口是`sqlite:config`，不会误改原Nova JSON文件。`/fire`是原客户端编排功能而非独立Lyra工具，现已接入Nitro持久工作流：独立验收，不将执行者自述当作证据，只由最后阶段续做，停止/错误/重启不自动重放外部操作。

## 安全与状态

工作台拥有服务端文件/命令/浏览器权限，**执行权限只给可信用户**，不是多租户沙箱。API使用账号Cookie认证、服务端角色/会话归属检查、CSRF/同源检查和请求/文件/流量预算，敏感配置脱敏返回。跨设备部署建议使用HTTPS并设置实际访问origin的`VEGA_PUBLIC_URL`，反代保留`Host`并为两个实时WebSocket入口启用Upgrade。

密码本与应用内订阅登录加密存于 SQLite。建议设置 `VEGA_VAULT_KEY` 为 32 字节 Base64 或 64 位 hex，并在数据库之外备份；不设置时随机生成并存在同一 DB，**只防误读/误传，不防拿到整个数据库的攻击者**。丢失外部密钥会使凭据不可恢复。普通 API 配置可以含明文密钥，优先环境变量引用。跨机 X25519 协议与原项目一样信任中转站不替换公钥，不具备带外身份认证。

任务中读取的密码只在当次运行的内存中供后续授权工具使用，写入会话/事件/计划前脱敏；原始 Token 不写进长期记忆。中断时会补齐不确定工具结果，续做不得自动重放外部提交；停止/失败/取消可以原任务续做，重新派发为新任务必须显式确认。
