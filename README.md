# Vega

Vue **3.6.0-rc.14 / Vapor** 前端 + **Nitro 2.13.5 / Node.js 24** 服务端。前后端一次构建、同源部署；业务状态保存于 **SQLite**（默认）或 **MySQL 8**，不依赖 Go、Rust、Tauri 或原项目目录运行。

## 运行

```powershell
npm ci
npm run build
$env:NITRO_HOST = '127.0.0.1'
$env:NITRO_PORT = '8080'
$env:VEGA_DB = 'D:/data/vega-nitro.db'
$env:VEGA_TOKEN = '<至少16个字符的随机访问令牌>'
npm start
```

访问 `http://127.0.0.1:8080`。首次打开时，使用`VEGA_TOKEN`（未配置则看启动日志中的初始化令牌）创建首个管理员，之后使用**用户名和密码**登录；初始化令牌不再能访问普通API。登录由HttpOnly、SameSite=Strict Cookie保存，每次成功登录后重新计算7天有效期（不是从首次登录固定计时），刷新页面和服务重启后仍有效；改密码/停用/改角色会撤销旧登录。部署请复制**整个 `.output`**（包括 `server` 与 `public`），在部署机安装匹配平台的原生 `sharp` 依赖。`npm run dev` 启动 Nitro；单独开发前端可运行 `npm run dev:web`，其 `/api` 代理到本机 8080。

Node >=24.10，使用内置 `node:sqlite`，无需另装数据库。默认数据库为工作目录的 `vega.db`，支持通过 `VEGA_DB` 指定位置。**不会自动转换或覆盖 Go 版/原 Nova 的数据库**；检测到不兼容数据库会拒绝启动，请指定新文件。

### 数据库配置

所有数据库读写都是异步的，不阻塞主线程：SQLite 在独立的 worker 线程中执行（WAL 模式），MySQL 使用连接池。

| 变量 | 说明 |
| --- | --- |
| `DB_TYPE` | `sqlite`（默认）或 `mysql` |
| `VEGA_DB` | SQLite 数据库文件（默认 `vega.db`）。**两种数据库下**，上传/归档文件都保存在它所在目录的 `files/` 下，需持久化并备份 |
| `MYSQL_URL` | 例如 `mysql://vega:密码@127.0.0.1:3306/vega`（密码中的特殊字符需 URL 编码）；设置后忽略下面的分项 |
| `MYSQL_HOST` / `MYSQL_PORT` / `MYSQL_USER` / `MYSQL_PASSWORD` / `MYSQL_DATABASE` | 分项配置，默认 `127.0.0.1` / `3306` / `root` / 空 / `vega` |
| `MYSQL_POOL_SIZE` | 连接池大小，默认 10 |

MySQL 需要 **8.0.19 及以上**（不支持 MariaDB），数据库须事先创建（建议 `CHARACTER SET utf8mb4`），首次启动自动建表。只支持单个 Vega 进程连接同一个库。`docker compose -f docker/docker-compose.mysql.yml up -d --build` 会连同一个 compose 文件里自带的 MySQL；用外部已有 MySQL 则 `docker build -f Dockerfile.mysql -t vega:mysql .`，镜像只默认 `DB_TYPE=mysql`、用户和库都是 `vega`，运行前必须用 `MYSQL_URL` 或 `MYSQL_HOST`（以及 `MYSQL_PORT`/`MYSQL_PASSWORD`）指向外部库。

数据库结构版本为 6，**不做旧版本迁移**：版本不符的非空库会拒绝启动且不修改，请使用新库。

## 实时通信

登录后通过 `/api/events` 的 SSE 事件流推送对话与牛马实时事件，上行只有普通 HTTP 请求（没有 WebSocket，也没有定时轮询）。票据为一次性、15 秒有效并绑定登录与 CSRF；大附件、大请求及超过 256KiB 的 GET 响应继续使用 HTTP，登录/注销等 Cookie 操作也保留 HTTP。写操作使用单次请求 ID，断线只重新同步状态，不自动重放，结果不确定时须先核对。原业务权限与输入校验不变。

## 本机执行端

各台电脑启动新版 `vega-local` 后，只需在该电脑网页登录一次并确认站点授权。前端仅传递一次性登录票据，客户端直接向后端换取设备凭据、持久保存并通过 `/api/local-agent/socket` 建立独立连接；之后**关掉网页、浏览器后台休眠、客户端或服务端重启都不依赖网页**，联网后客户端自行重连。手机也可提交任务；新任务默认在云端，暂停后可在任务详情选择在线客户端交接到本机。心跳容忍30秒，短暂断连保留原任务并给同一客户端实例60秒重连；执行中的操作不重发，客户端仅补传尚未确认的结果，连接恢复后自动续做；响应超时也先尝试一次重连接回结果，而非立即判定中断。超过恢复期限、客户端进程重启或结果仍不确定时，普通对话暂停等待确认；牛马任务按恢复点自动恢复：云端可用时先接到云端继续（云端没有本机文件副本时按步骤记录续做，缺什么现场核对，核验不了会停下来问你），设备回连后自动切回本机继续，两边都不自动重放中断的操作，也不换到别的设备。需同时升级服务端、网页和客户端，升级后在电脑端重新握手一次。详见 [local/README.md](local/README.md)。

**客户端版本门槛**：默认要求客户端不低于服务端发布版本（服务端 `MIN_CLIENT_VERSION`，需与 `local/VERSION` 同时抬高，当前 `0.5.0`），低于该版本或未上报版本的客户端在握手阶段被拒绝，网页显示要求的最低版本与升级提示，旧客户端连上也不能执行任何任务；`VEGA_MIN_CLIENT_VERSION` 可覆盖默认值（设为空串表示不限制）。升级客户端后自动恢复，无需改服务端。

## 账号、登录与权限

首次创建管理员后，进入「账号与权限」添加账号、停用/启用、调整角色或重置密码；没有开放注册，也没有内置默认密码。用户名3–64个英文字符/数字/点/下划线/连字符，密码至少12字符、最多256个UTF-8字节。密码采用随机salt的scrypt存储，Cookie中的随机会话令牌只以SHA-256摘要保存于SQLite，密码和登录Cookie不返回到账号列表。

| 角色 | 网站权限 |
|---|---|
| 管理员 `admin` | 系统配置、订阅/技能、数字牛马、Chrome和团队管理（密码本由各牛马创建者在牛马页配置）；创建/停用账号、修改权限，查看全部会话，并授予其他账号会话只读权限 |
| 操作用户 `operator` | 通过网站新建和运行自己的对话/Stage/Fire，查看自己的任务结果；不能直接调用管理员专属网站接口。已提交任务的内部工具集与运行机制不按网页角色裁剪 |
| 只读用户 `viewer` | 只能查看管理员明确授权的会话、其图片和实时事件；不能发消息、停止任务、创建会话或执行工具 |

会话、Stage/fork/Fire衍生会话按创建账号归属，实时事件流和截图BLOB也校验会话访问权限；分享只授予查看，不授予执行。衍生会话继承创建时的查看授权，之后单独管理。旧版本无归属的会话/截图只有管理员可见，不会因升级自动公开给新账号。SQLite新增账号/登录表，升级前仍建议备份数据库。

注销只撤销本次网页登录，不关闭已经独立授权的客户端。密码修改/管理员重置、角色变更或停用撤销该账号的网站登录、实时查看及设备凭据；服务端内部任务仍保持原执行机制，但设备授权撤销或断连超出恢复期限后，会暂停依赖该设备且结果不确定的操作，不自动重试；最后一个启用的管理员不能被停用或降级。内部agent、数字牛马、定时任务和恢复流程不依赖是否有人在线，保持原工具集/执行机制；只有网站上明确调用停止/取消等业务操作才改变执行状态。登录有失败尝试和并发KDF限流，用户名或密码错误统一返回失败；网站修改API要求CSRF token并检查Origin，不依赖前端隐藏按钮。

**Docker 镜像按用户隔离云端文件执行身份**：账号首次进入可执行工作台时，自动分配持久 UID/GID 和私有工作区；文件、shell、技能、MCP 子进程与浏览器使用对应身份，初始化失败不退回公共身份。网站 RBAC 仍负责页面/API和数据授权，不等于完整沙箱；网络与内核仍共享，不应向任务暴露宿主挂载、管理凭据。非 Docker 直接启动仍是共享系统身份，只适合可信账号。只读用户没有提交任务或执行工具的网站入口。

### HTTPS与反向代理

网站和客户端均支持HTTP与HTTPS；公网建议使用HTTPS。`VEGA_PUBLIC_URL`设置为实际访问的HTTP(S) origin（如`http://vega.example.com:8080`或`https://vega.example.com`，不带路径），服务按该origin检查请求，仅HTTPS使用Secure Cookie。**HTTP下登录信息、设备凭据与命令明文传输，存在被窃听或篡改的风险。** 不要信任任意客户端传入的Forwarded头。反代保留Host，并让`/api/events`、`/api/chrome/live`、`/api/local-agent/socket`、`/api/local-agent/relay`的响应**不缓冲**（服务端已发`X-Accel-Buffering: no`，nginx 还需`proxy_buffering off`）；设备连接还需保留Authorization头，流量中继隧道还须转发`X-Vega-Relay`。直接本地HTTP开发可不设置此变量。

**实时通道与超时**：网页的所有API都走普通HTTP，`/api/events`只推送事件，不再转发API请求。服务端每20秒发送一次心跳并做协议级ping，网页75秒收不到任何消息才重连；重连带上次的事件序号，2分钟/5000条以内的断线只补发漏掉的事件，不整页刷新。牵牛星客户端每5秒心跳，大于256KB的结果改为`POST /api/local-agent/result`上传（同样需要保留Authorization头，并允许最大48MB请求体）。反代请据此设置：

- 事件流要能一直活着（nginx `proxy_read_timeout 300s; proxy_send_timeout 300s; proxy_buffering off;`），且不要压缩或缓冲 SSE 响应；
- `client_max_body_size 90m`（聊天附件上限）以上，`/api/local-agent/result`的请求体可达48MB；
- 客户端 Origin 必须与实际上传 URL 同方案同主机（`http`≠`https`）：客户端**不跟随**跨站/升格重定向；若网站强制 HTTPS，配对 Origin 也须是 `https://…`，否则大结果上传会得到 301/302 并在「连接仍正常」下表现为浏览器操作超时；
- 反代须原样转发 `Authorization` 与 `X-Vega-Instance`；不要给该 POST 加浏览器 Origin（原生客户端鉴权要求无 Origin、无 query）；
- 服务端已对超过2KB、且浏览器接受gzip的JSON接口响应做gzip（会话历史一般压缩到1/3以下，1200条的历史约2.0MB→0.6MB），反代无需再压缩`/api`；若反代也开启gzip，已带`Content-Encoding`的响应会被跳过；
- 每个账号最多同时保持12个实时事件连接（多开标签页/设备合计），超出的新连接收到4429并在30秒后重试；无响应的僵尸连接会在下一次心跳时被清理。

原`VEGA_TOKEN`现在仅用于**首个管理员初始化**和只返回就绪/扩展连接状态的`GET /api/health`，不再是普通网站API的管理员后门。容器启动/健康检查已改用health入口，不需要保存网站账号密码；Token轮换不撤销SQLite中的账号登录。

## Linux / Docker 自动安装扩展

项目根目录的 `Dockerfile` 会在Linux内构建Nitro和原生依赖，并在独立Go阶段编译Windows x64、Linux x64/ARM64、macOS Intel/Apple Silicon客户端；部署后从主导航「资源」直接下载当前镜像配套版本，无需另跑Go构建或访问外部Release。镜像按用户身份在同容器内按需启动专用无头 Chromium，自动加载现有扩展，用户之间不共享 Profile；启动健康检查验证身份执行器就绪，不要求先启动公共浏览器。无需手工打开扩展管理页，只发布8080，不暴露CDP/回环桥接端口。数据库、身份映射、浏览器登录态与工作目录通过原有两个卷持久化。

```sh
docker build --pull -t vega:local .
docker run -d --name vega --shm-size=1g \
  -p 127.0.0.1:8080:8080 \
  -e VEGA_TOKEN='替换成至少16字符的随机令牌' \
  -v vega-data:/data -v vega-workspace:/workspace vega:local
```

这是**自动加载容器里的扩展，不会改宿主浏览器**。默认保留Chromium沙箱，宿主限制namespace/sandbox时会停止并报错，不静默降低安全性；数据卷和basic password store的浏览器登录态须保护。完整操作、权限和沙箱说明见 [`docker/README.md`](docker/README.md)。

## 配置模型

设置页通过表单管理服务商、接口地址、密钥和模型，支持获取/搜索/手动添加模型与修改能力、长度参数；场景模型通过下拉选择，支持档位和备用顺序，浏览器场景只显示图片模型。高级请求头/厂商参数按需展开。底层仍支持旧`provider.options.baseURL/apiKey/headers`与顶层写法、嵌套分类、`limit.context/output`、`modalities.input`和`variants`。密钥可用`{env:NAME}`/`${NAME}`引用；`__stored_secret__`保留已有密钥。经验图谱独立导航，设置排在最后；界面不再提供目录配置或技术机制说明。

```json
{
  "model": "openai/gpt-4.1",
  "provider": {
    "openai": {
      "api": "openai-completions",
      "options": {"baseURL": "https://api.openai.com/v1", "apiKey": "{env:OPENAI_API_KEY}"},
      "models": {
        "gpt-4.1": {"limit": {"context": 128000, "output": 8192}, "modalities": {"input": ["text", "image"]}}
      }
    }
  },
  "scenes": {"lightweight": ["openai/gpt-4.1"], "coding": ["openai/gpt-4.1"], "computer": ["openai/gpt-4.1"]},
  "contextMode": "auto",
  "mcp": {},
  "image": {"baseURL": "", "apiKey": "", "models": []}
}
```

场景数组按顺序降级；电脑场景须支持图片。变体 ID 为 `provider/model/variant/high`。厂商目录支持预设服务商，账号目录优先于 models.dev 能力补全；Coding Plan 等没有 `/models` 的端点可回退 models.dev，但不能用目录补回账号无权限模型。

### 专有订阅

设置 →「服务商」选择 **CodeBuddy / WorkBuddy**（统一入口）或 Devin。CodeBuddy / WorkBuddy 登录时选择 CodeBuddy 中国站、国际站或 WorkBuddy，点击登录会立即打开窗口、绑定本次来源/站点并自动检查结果，成功后直接导入账号模型。两者通过 Vega 服务端原生直连上游，不启动本地代理、CLI 或桌面程序；「使用 Vega 已有登录」只复用 Vega 保存的网页登录（或显式环境变量凭据），不读取部署端 CLI 登录。远程 Devin 默认回调网站的`/api/providers/callback/devin`；公网部署需设置正确的`VEGA_PUBLIC_URL`并使用 HTTPS。回调独立校验一次性 state/PKCE，轮询绑定发起管理员；若官方限制回调地址，可改用手动回调并粘贴完整跳转地址。真实账号及第三方回调白名单仍需在目标部署验收。

- **CodeBuddy / WorkBuddy**：共用原生传输，两个通道的加密会话、续期和账号/企业请求头独立，不混用账号。不读取 CLI 设置、安装包或桌面端加密登录；模型及能力只取自 `/v3/config`，仍遵守服务端 `agents.cli.models` 范围（不是读取本机 CLI）。默认模型失效时回退到列表首项，旧保存的默认别名映射不会覆盖新目录；显式选择不可用模型仍会报错。支持 reasoning summary、重复工具 ID/包装 JSON 归一化。
- **Devin**：读取 CLI TOML 或应用内登录；直接执行 Connect/Protobuf 推理，回传历史可见 reasoning（消息字段 5），校验 gzip 帧、trailer、停止原因与工具完整性；CLI 不可用时使用原项目的版本化模型快照。**Adaptive 自动路由与参考项目一样不支持，必须选具体模型。**
- **Codex / Claude Code**：按 CLI 配置识别自定义 API，否则在每次请求前只读订阅认证。官方端点固定，不执行 apiKeyHelper，不代替 CLI 轮换 refresh token；过期须先在 CLI 更新。macOS 支持原项目覆盖的钥匙串形态，其它 keyring 后端不会猜测。

CodeBuddy / WorkBuddy 的 `*_AUTH_TOKEN` / `*_API_KEY`、`*_MODEL` 和 `NOVA_*_ENDPOINT` 环境变量仍可显式设置；`*_CONFIG_DIR`、`NOVA_*_AUTH_FILE`、`NOVA_*_PACKAGE`、`WORKBUDDY_EXE` 和旧 WorkBuddy 路径设置不再影响它们。旧 `workbuddy` 预设仍可加载，设置页保存时归一到 `preset: "codebuddy"`、`options.codebuddySource: "workbuddy"`，保留 Provider ID、模型和会话引用，不删除或合并已有配置实例。原先只在 CLI/桌面端登录的用户需在 Vega 登录一次；原配置与凭据不会被删除。云端缺失的模型能力采用保守默认值，不再从安装包补齐。

Codex / Claude Code / Devin 的 `CODEX_HOME`、`CLAUDE_CONFIG_DIR`、`DEVIN_CONFIG_HOME` 等定位方式保持不变。HTTP(S)/ALL/NO_PROXY 环境变量优先，否则读取 Windows/macOS 静态系统 HTTP(S) 代理，下一次请求重新判断；不跟随专有订阅请求的重定向。

### 数字牛马工作台

用户创建并选择牛马，直接交代目标；对话用于沟通和调度，执行会话由牛马内部创建/续写。管理员创建的是**团队牛马**，所有账号可见；普通成员创建的是**个人牛马**，仅本人和管理员可见。团队牛马的设置、删除与浏览器登录环境由管理员管理，执行成员可以交代任务，只读账号只能查看。牛马添加即用，不再有启用开关或工作时间；职责的定时触发和任务暂停仍保留。旧单例数据原地作为团队“默认牛马”，任务和会话ID不变；网站不再提供历史会话或手动建会话入口，旧数据和兼容API仍保留。管理员另有只读“调试会话”页，可查看每个牛马真实的沟通/执行/浏览器会话及原始工具记录。

不再按牛马配置 Master/Follower：新任务默认在云端，已有任务保持原执行位置。需要在本机运行时，在任务详情先暂停正在执行的任务，选择同账号在线客户端并点击「交接」，暂停的任务再手动继续。交接会把已开始的云端工作区业务文件复制到客户端工作目录；同名冲突保留双方文件，跳过依赖、构建产物与常见凭据，超出 2000 个文件、单文件 4MiB 或合计 16MiB 时拒绝交接。文件系统和浏览器一同绑定所选设备，登录态只按授权站点补齐，不覆盖目标端已有的有效登录。云端借用本机 `~/.ssh` 和网络仍需使用已授权的客户端。

牛马页提供明确确认的删除入口；正在执行时须先停止任务和对话。删除会清除牛马职责、记忆、任务、沟通/执行会话和独立浏览器Profile，默认牛马删除后也不会重生；该牛马自己的密码本一并删除，不会删除项目文件。

只复用一套执行引擎和共享调度循环，不为每个牛马启动后端。全局最多3个任务并发，轮转调度牛马；同目录的写任务、同牛马的浏览器任务串行，不同牛马的浏览器可并行。等待补充、审批、外部作业时释放名额，到时续做原任务。牛马沟通会话不能直接执行命令或网页操作；任务必须以完整已验证计划和 `complete` 证据交付，普通结束一轮不算完成。步骤需要产出成果时，可在任务完成前保存文本或工作区文件快照，在来源对话和任务详情中作为独立产物展示，文本可单独导出、文件可下载，任务继续执行；输出产物不等于已执行或验证后续步骤。文件单个上限 25MiB、每次合计 64MiB；本机文件产物需要升级到支持工作区安全读取的客户端。网页可将文本导出为 Markdown、HTML、PDF、DOCX 或 XLSX，其中 Markdown/DOCX 图片保留链接、XLSX 有表格时仅导出表格。

任务正式结束（完成、取消或封存）后，系统自动关闭该任务确认新建的浏览器标签页，包括操作中打开的新页；停止、失败、等待审批、补充或外部结果时保留页面，以便核对、交接或续做。原有标签页、被其他任务操作或通过 Vega 浏览器界面接手查看的标签页不会自动关闭。浏览器离线或被占用时待连接/占用恢复后再尝试；关闭结果不确定时不盲目重放。只有启用该功能后能确认归属的新页会被追踪，未确认归属或此前已经打开的页面不会关闭。页面关闭会丢弃其中未保存的内容，登录态不因此删除；直接在自己的 Chrome 里接手任务新建的页面无法被识别，请先保存编辑内容。

**通用自愈**复用原任务和执行会话：意外中断、超时、未知异常或未验证交付时，持久保存原因/尝试次数/恢复点，进入“检查现场→诊断→最小修复→验证→续做”的恢复模式。单轮最多15分钟，自动恢复最多3次，30/60/120秒退避，恢复窗口30分钟；耗尽后等待用户。服务重启不清零预算，停止/取消/驳回审批不自动恢复。外部操作结果不确定先核验，不能自动重放提交。进程本身的拉起仍由系统服务或容器负责。

**每牛马独立浏览器**：按需启动独立Chromium进程，登录态存于 `<数据库目录>/employee-browsers/<牛马ID>`（Docker 用户隔离模式使用 `/workspace/.vega-users/<用户ID>/home/browsers/<牛马ID>`），停止和重启不清除Profile。需要支持 `Extensions.loadUnpacked` 的现代Chrome/Chromium，可用 `VEGA_CHROME_PATH` 指定；Windows已验证Chrome156。牛马生成的扩展副本只连接自己的认证回环桥，启动调试使用私有管道，不暴露CDP端口；原始扩展保持不变。浏览器故障只影响所属牛马，恢复后重新观察，不重放页面操作。密码本按牛马独立配置（牛马页「密码本」，仅牛马创建者可查看列表和修改）：牛马的对话、任务和电脑会话只能取用自己的条目，须按条目的使用条件取用；凭据支援收到的临时条目存进请求方牛马且仅限原任务；删除牛马同时删除其密码本。普通会话不归属牛马，不提供密码本。旧版全局密码本在升级后首次启动时复制给当时所有牛马（临时条目只给所属任务的牛马）后删除。隔离Profile不等于操作系统沙箱，同业务账号仍共享服务端数据。

### Chrome（兼容入口）

1. Chrome 与 Nitro 桥接必须在同一电脑/回环环境，运行 Nitro。
2. 用本机客户端并保持默认的**无头浏览器**时不需要这一步：客户端自己解压内置扩展并装进它拉起的隐藏 Chrome。要改走你自己开的 Chrome（「连接授权 → 浏览器」选「用我自己开的 Chrome」）时，才需打开 `chrome://extensions`，开开发者模式，加载项目 `local/extension/vega-chrome`；部署产物在 `.output/public/extension/vega-chrome`，资源页也下载同一个包。扩展同时内置在本机客户端里，「连接授权 → 授权 → 浏览器扩展」会为在线的 Windows 客户端创建本机安装任务。
3. Vega 的扩展有自己的 ID（manifest `key`）和端口 47753–47762，只与 Vega 客户端配对；Nova 的扩展用 47653–47662，两边同时安装也不会互相连接。`VEGA_CHROME_PORT` 可指定单一回环端口。
4. 无痕操作须在扩展详情开启无痕权限；多浏览器同时连接时优先 Chrome。控制目标始终是已观察到的稳定 tag，不猜当前激活页。

只操控网页，**没有桌面工具或原生系统对话框能力**。截图/完整DOM与大输出可按返回的 `sqlite:` 路径回读；二进制存在SQLite。文件上传限当前工作目录内的普通文件并校验真实路径。输入/提交超时会报告不确定性，不能自动重放。牛马任务使用自己的私有浏览器，不争抢宿主桌面；旧的物理桌面空闲/锁屏检测保留给兼容执行环境。没有引入Jianlai或桌面输入模拟。

### 浏览器查看与远程操作

在牛马工作空间打开「浏览器」（执行成员仅限自己的牛马）；兼容全局浏览器仍仅管理员可访问。选择tab后通过同源 SSE 事件流持续更新视口画面，不再等待每次操作后的单张截图。默认只查看：电脑用滚轮以鼠标位置为中心缩放预览、按住鼠标拖动；手机用双指捏合缩放、单指拖动画面，手势只改变预览、不缩放整个应用窗口；「还原视图」恢复原始缩放和位置，键盘也支持 +/- 缩放、方向键平移、0 还原。只有点击「开始操作」后，点击、双击、右键、按住拖动、滚轮、文字输入与常用按键才会直接同步到网页；按钮随即变为「退出操作」，退出立即恢复查看模式。开始、退出操作均保留当前预览比例和位置，坐标按实际缩放换算；可通过「还原视图」恢复原始比例。鼠标拖动超过几像素即按拖动处理，不额外发送单击。拖动确认按下后，移动使用有界的最新位置流，不逐次等待往返；弱网下合并过时位置，松手优先发送并在最终位置释放。结束后显示「同步中…」直到释放结果对应的新画面显示，再接受下一次拖动，避免把第二次手势排到旧画面上。手机长按画面不打开图片菜单、不向网页发送右键或单击；操作模式短按点选网页，按住约半秒后移动会像鼠标按住拖动，松手、触摸取消或加入第二根手指会释放鼠标；未长按的滑动不会误发拖动。网页翻页请用「网页上滚/下滚」；也可前进/后退、重载及跳转HTTP(S)网址。操作模式下辅助输入框常驻：先点网页输入框，再点辅助框打开手机键盘，支持中文、输入法和粘贴；点「发送文字」只输入内容、不自动回车，提交须单独点「回车」。画面使用内存中的JPEG截图流，最高约10帧/秒，实际速度随页面、网络和扩展响应变化，**不是高帧率视频或桌面远程控制**。无需升级现有Chrome扩展。

WS连接先通过带CSRF校验的POST取得15秒有效、一次性且绑定当前账号和浏览器实例的票据；握手同时校验Cookie和Origin，注销/撤权会关闭已连接通道。慢客户端每次只保留一张待确认画面，不积压帧或点击；实时画面不写入SQLite。输入按连接序号去重，并校验用户实际显示过的帧、网页/视口和焦点，断线和结果不确定时不重放；原HTTP截图/操作接口仍保留，继续使用原像素校验规则。

手动控制期间独占**该标签页**的 Chrome 操作锁，同一标签页的 agent 后续操作等待；不同标签页的人工控制与 agent 任务互不阻塞，多 tab 可同时查看或操作。退出、断线、页面隐藏或30秒未操作会释放控制权，并在必要时松开鼠标。手动操作会使同页 agent 的旧观察失效，但纯查看不会覆盖 agent 的 ref/截图。获取后台/最小化标签画面可能会显示 Chrome 窗口并切到该页。

**客户端无头浏览器（默认）**：本机客户端 `vega-local` 自己拉起一份隐藏的 Chrome（独立 profile 在客户端数据目录，首次启动从本机 Chrome 复制 Cookie/Local State，闲置 15 分钟后回收（正在操作浏览器的那一轮不回收）），通过 CDP 装好内置的 Vega 扩展。浏览器工具因此不需要你打开窗口或手动装扩展，也不会碰你自己的标签页和窗口；登录态留在这个 profile 里，客户端重启后仍在。要改走你自己打开的 Chrome，在客户端「连接授权 → 浏览器」选「用我自己开的 Chrome」；两种方式不自动互相回退，选中的浏览器连不上时该步直接报未执行。Windows 按 `VEGA_CHROME_PATH` 或常见安装路径找 chrome.exe，Linux/macOS 找不到时用同一变量指定。Chrome 运行时 Cookies 数据库被独占，首次启动那次复制往往拿不到东西；这时客户端通过扩展在你自己的 Chrome 与无头浏览器之间**双向**同步登录态：你 Chrome 里的 Cookie 进无头 profile，你在无头浏览器里新登录的站点也写回你自己的 Chrome。两个方向都只补对方缺少的（或对方那份已过期的），有效会话互不覆盖；写回去不需要新开窗口或页签，客户端只借用后台页签附着一次就松开。同时连了多个浏览器时只跟 Google Chrome 优先的那一个同步（一个无头 profile 不吃多份登录，也不会把 A 的登录写进 B）；你在 Chrome 里退出登录后，客户端不会再把它种回去；每轮操作结束只在无头里真的多了新登录时才再写一次。前提是你的 Chrome 里装了 Vega Chrome 扩展（客户端「连接授权 → 授权 → 更新浏览器扩展」），并且有至少一个后台页签可借读（当前激活的那个不算）；只同步 Cookie，不含 localStorage、IndexedDB 和密码。同一无头实例每 10 分钟最多同步一次，每轮浏览器操作结束后也会再同步一次，每次启动新实例再同步一次，结果写在设置页「浏览器」卡片和 client.log 里。

**无头模式**：设置 `VEGA_BROWSER_MODE=isolated` 后，服务启动一个私有无头 Chrome（与 Docker 同一套扩展协议、独立 profile 目录 `<数据库目录>/chromium`），不占宿主桌面。Linux/Windows/macOS 都支持；Windows 上通过 `VEGA_CHROME_PATH` 指定 chrome.exe，未设置时自动探测常见安装路径。无头实例可多 tab 并行截图和输入；cookie/登录态持久在私有 profile，不与用户日常浏览器共享。Docker 模式同样使用此变量，行为一致。

远程部署仍只需现有网站端口。反向代理须为`/api/events`、`/api/chrome/live`、`/api/local-agent/socket`及`/api/local-agent/relay`保持长连接并关闭响应缓冲（`proxy_buffering off`，超时不低于 300 秒）且保留Host；设备连接还须保留Authorization，中继隧道还须转发`X-Vega-Relay`；公网建议配置正确的`VEGA_PUBLIC_URL`并使用HTTPS，**不要暴露Chrome调试端口或回环扩展端口**。意外断线且没有进行中的操作时自动重连（最多3次），页面切回前台也会自动重连；可能已执行的操作仍要求人工核对，不自动补发上次操作。画面不变时只发送不含图片的确认帧，静止约2秒后采样降为每秒2帧。

### MCP 和技能

- MCP 配置为 `{"server": {"command":"node", "args":["server.js"], "env":{}}}` 或 `{"server":{"url":"https://example/mcp","headers":{}}}`。先 list → describe → call；定义变化须重新 describe。只读模式须由用户配置本地 `readOnlyTools` 允许列表，远端 `readOnlyHint` 不是授权。
- 不提供独立图片生成/改图服务。聊天附图、视觉模型、read图片和Chrome截图不受影响；旧图片服务配置不再使用，历史图片保留。

## billion-context / ACP 与查漏记录

配置`"contextMode":"acp"`启用模型主动管理：模型收到稳定`[m00001]`引用与`<context-budget>`提示，用`compress`选择已完成单元并写摘要；可把`bN`作为边界精炼到T2/T3。`decompress`恢复原文及子块，`search_context`返回命中片段，`recall`按预算带回原文和工具配对，较长原文可用`read sqlite:message/序号`按行读取。账本、应急投影和token校准均保存在SQLite，不会覆写消息。

这是**历史虚拟化/分层压缩机制**，不是将模型原生窗口提升到十亿token。字符估算、图像占位成本和实测锚点之外的增长仍是估算；应急机械压缩会明确标注细节缺失，原文可回读。与所参考的Lyra一样，不实现上游kernel未被使用的young/old标签和默认关闭的按块数触发器。已有Vega数据库的旧块仍可恢复；新的压缩使用原子单元、至少40字摘要和70%收益校验，保护最近2个单元及未完成工具调用。

本轮还补上了：中断工具配对与孤儿修复、完成轮次OpenAI reasoning裁剪、每标签最近2份Chrome DOM投影、413旧图恢复、输出耗尽单次降思考且不重放工具、同会话MCP连接/describe状态保留、候选场景/同模型和只读路由、fork上下文账本、read的50KiB实际行边界与路径归一化。逐项来源和验收边界见`reference/parity-audit.md`。

`/setup`只允许更新provider/model/scenes；配置入口是`sqlite:config`，不会误改原Nova JSON文件。`/fire`是原客户端编排功能而非独立Lyra工具，现已接入Nitro持久工作流：独立验收，不将执行者自述当作证据，只由最后阶段续做，停止/错误/重启不自动重放外部操作。

## 安全与状态

工作台拥有文件/命令/浏览器执行能力。Docker 用户目录通过独立 UID/GID 隔离，但不是网络、资源或内核级多租户沙箱；非 Docker 的共享执行身份只用于可信用户。API使用账号Cookie认证、服务端角色/会话归属检查、CSRF/同源检查和请求/文件/流量预算，敏感配置脱敏返回。跨设备部署建议使用HTTPS并设置实际访问origin的`VEGA_PUBLIC_URL`，反代保留`Host`并让实时事件流的响应不缓冲。

密码本与应用内订阅登录加密存于 SQLite。建议设置 `VEGA_VAULT_KEY` 为 32 字节 Base64 或 64 位 hex，并在数据库之外备份；不设置时随机生成并存在同一 DB，**只防误读/误传，不防拿到整个数据库的攻击者**。丢失外部密钥会使凭据不可恢复。普通 API 配置可以含明文密钥，优先环境变量引用。跨机 X25519 协议与原项目一样信任中转站不替换公钥，不具备带外身份认证。

任务中读取的密码只在当次运行的内存中供后续授权工具使用，写入会话/事件/计划前脱敏；原始 Token 不写进长期记忆。中断时会补齐不确定工具结果，续做不得自动重放外部提交；停止/失败/取消可以原任务续做，重新派发为新任务必须显式确认。
